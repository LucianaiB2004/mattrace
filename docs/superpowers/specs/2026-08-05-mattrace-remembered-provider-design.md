# MatTrace 模型配置记忆与真实分析传输设计

## 目标

用户输入一次 API 网关、模型名称和 API Key 后，当前浏览器自动保存并在后续访问中回填，无需重复输入。真实分析在本地开发环境中自动绕过第三方网关 CORS 限制，同时不把凭证写入仓库、静态 HTML、Skill、项目快照或报告导出。

## 配置记忆

- 使用独立且带版本号的 `localStorage` 键保存 `{ gateway, model, apiKey }`。
- 页面初始化时读取并校验配置；无有效存档时使用公开默认网关和模型，Key 为空。
- “应用配置”保存当前配置；连接测试不单独持久化尚未应用的内容。
- “清除 Key”同时清除组件状态和浏览器存档中的 Key，保留网关与模型。
- 配置页显示“Key 已保存在当前浏览器”的明确提示，并说明 localStorage 不是加密保险箱。
- 项目快照、Skill 工作区、ZIP、JSON/CSV/Markdown 导出及测试产物禁止包含 Key。

## 真实分析传输

- 用户界面始终展示和保存原始网关 `https://ai.chipcloud.cc`，不要求用户理解本地代理地址。
- 在 `localhost` / `127.0.0.1` 开发页面且目标为默认网关时，应用自动将 API 请求发送到同源 `/api/ai/*` 或受限本地代理；静态 GitHub Pages 继续直连用户填写的网关。
- 代理只接受本地 MatTrace 来源、只转发 `/v1/models` 与 `/v1/chat/completions`、不记录正文和 Authorization。
- 代理必须支持网关的长响应连接；通过真实三论文请求验证，不以短 `/models` 请求代替。
- 请求失败时显示可恢复错误并保留文档；不得回退到伪造数据。

## 界面调整

- 删除页面右上角“保存当前项目”和“恢复项目”按钮。
- 右侧“项目与隐私”卡片继续提供保存、恢复和删除存档，避免功能丢失。
- 模型配置按钮继续显示当前模型；配置弹窗增加保存状态与本地存储风险说明。

## 验收

1. 输入配置并应用，刷新页面后网关、模型和 Key 自动回填。
2. 清除 Key 后刷新，Key 保持为空。
3. 敏感信息审计确认项目快照、Skill、ZIP、导出和仓库中没有运行 Key。
4. 删除顶部两个重复项目按钮，右侧项目管理仍可完整使用。
5. 使用三篇内置论文在浏览器中完成真实分析，结果通过材料、性能、单位、条件、来源、页码、证据、可信度合同。
6. 动态站点与静态站点的全量自动化测试通过；静态站点在网关不支持 CORS 时明确提示部署限制。

## 非目标

- 不把 Key 编译进客户端资源或提交到 Git。
- 不声称 localStorage 提供加密保护。
- 不增加账户、云端凭证同步或多设备同步。
