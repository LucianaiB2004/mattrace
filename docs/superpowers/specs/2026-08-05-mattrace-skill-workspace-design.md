# MatTrace 完整 Skill 文件夹工作台设计

## 目标

将现有仅能预览和编辑简化 `SKILL.md` 的管理页面，升级为可审查、可编辑、可演示并可导出完整文件夹的 Skill 工作台。最终交付物必须是完整、可复用的 `material-evidence-extractor` Skill，而不是孤立 Markdown。

## 交付目录

工作台与下载 ZIP 使用同一份文件清单作为唯一数据源：

```text
material-evidence-extractor/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── references/
│   └── output-schema.md
├── examples/
│   ├── records.jsonl
│   ├── comparison.csv
│   ├── evidence-report.md
│   ├── missing-and-conflicts.md
│   └── review-queue.csv
└── scripts/
    ├── extract-evidence.mjs
    ├── normalize-record.mjs
    └── build-deliverables.mjs
```

`SKILL.md` 必须明确支持输入 3–10 篇论文、专利或 TDS，抽取材料组成、实验条件、性能指标、单位、测试条件、来源页码、缺失字段和可信度，并生成 JSON/CSV、证据链、缺失条件报告、可信度评分和可复查引用。

## 管理界面

抽屉采用左侧文件树、右侧内容区：

- “概览”展示任务、输入范围、核心能力、输出交付物和目录完整度。
- “文件”展示完整目录树；点击文件在右侧预览。
- `SKILL.md`、字段规范和 Agent YAML 可在浏览器内编辑、保存与恢复默认。
- 示例和核心代码默认只读，避免演示时误改运行合同；仍可完整查看和复制。
- “输出示例”提供 JSONL、CSV、证据报告、缺失与冲突报告、复核队列的快捷入口。
- “核心代码”提供抽取、规范化、可信度及交付物生成逻辑的快捷入口。
- 保留单独导出 `SKILL.md`，新增一键导出完整 `material-evidence-extractor.zip`。

## 数据与安全

- Skill 文件清单由领域模块管理，页面与 ZIP 构建共用同一数据源，防止展示内容与下载内容漂移。
- 浏览器只持久化允许编辑的文本文件；恢复默认时清除这些覆盖。
- 所有保存和导出都执行敏感凭证扫描。API Key 只保存在当前页面运行内存，不进入 localStorage、项目快照、Skill 文件或 ZIP。
- ZIP 保持规范相对路径，不包含构建产物、测试报告或用户上传文档。

## 真实分析验证

在本地页面临时输入用户提供的网关、模型和 API Key，使用三篇内置真实论文运行分析。验收内容包括：

1. 模型连接成功，真实分析请求使用完整论文解析文本。
2. 结果包含材料、工艺/组成、性能、值与单位、测试条件、文档名、页码、证据文本和可信度。
3. 缺失条件和冲突不由模型臆造；没有冲突时明确返回空清单。
4. JSON、CSV、Markdown 导出与证据链保持一致。
5. 重命名、保存、清空、恢复后来源引用仍能闭环。
6. 浏览器刷新或项目存档中不存在 API Key。

若第三方模型返回不符合结构合同的内容，页面应给出可恢复错误，不把不完整结果伪装成成功。

## 测试策略

- 领域测试：文件清单、可编辑边界、敏感信息拦截、ZIP 路径与内容完整性。
- 结构测试：仓库真实 Skill 目录包含规格要求的全部文件。
- 组件端到端：文件树切换、预览、编辑、保存、恢复、单文件导出和 ZIP 下载。
- 完整回归：构建、Lint、单元测试、动态站点 E2E、GitHub Pages 静态站点 E2E。
- 浏览器人工验收：使用临时 API Key 运行真实分析并逐项检查输出合同。

## 非目标

- 不在浏览器内执行 Skill 的脚本文件。
- 不建立服务端密钥存储或用户账户系统。
- 不把论文原文打包进 Skill ZIP。
