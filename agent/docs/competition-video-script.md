# MatTrace 黑客松 3 分钟演示视频脚本

> 建议成片长度：2 分 55 秒至 3 分钟。叙事顺序：痛点与创新 → 正式 Skill → Agent 操作 → 总结致谢。

## 一、录制前准备

1. 使用 1920×1080 分辨率录制，浏览器缩放设为 90%–100%，关闭无关标签页和通知。
2. 打开 `http://localhost:3000/`，提前确认 3 篇公开论文已经显示在文档工作区。
3. 提前在“模型配置”中保存网关、模型和 API Key。正式录制时不要展示 API Key；如必须打开配置窗口，应对 Key 区域打码。
4. 预先完成一次真实分析，确认结果可用；正式录制再运行一次。模型等待时间超过 8 秒时，后期加 2–4 倍速，并保留进度变化画面。
5. 准备代码编辑器，提前打开以下位置：
   - `skills/material-evidence-extractor/SKILL.md`
   - `skills/material-evidence-extractor/references/input-schema.json`
   - `skills/material-evidence-extractor/references/output-schema.json`
   - `skills/material-evidence-extractor/references/failure-cases.md`
   - `skills/material-evidence-extractor/scripts/score-uplift.mjs`
   - `skills/material-evidence-extractor/examples/`
6. 鼠标移动保持平稳，每次重点内容停留 2–3 秒。不要在视频里展示测试用假分数，也不要宣称尚未真实完成的 uplift 数值。

## 三、纯旁白连续版

以下是控制在 3 分钟内的推荐提词器版本。按自然但紧凑的语速朗读，操作间隙不必重复解释画面文字。

> 大家好，这是 MatTrace，一个面向材料文献与数据资产构建的证据优先型 AI Skill 与演示 Agent。
>
> 材料数据经常散落在正文、表格和脚注中，组成、工艺、性能与测试条件彼此分离，人工整理耗时且难以复查。普通大模型只说找到了什么，却不说明漏掉了哪篇，还可能直接比较不同条件的数据。MatTrace 的创新是覆盖与可比性审计：逐篇交代状态，逐条绑定原文，并在比较前核验条件、单位和不确定性。
>
> 比赛正式交付物不是网页，而是 material-evidence-extractor 完整 Skill；Agent 是评委的操作入口。Skill 严格接收三到十篇论文、专利或 TDS，抽取材料、实验条件、性能、单位、页码、缺失字段和可信度。
>
> 文件夹包含任务合同、输入输出 Schema、字段规范和失败案例。缺失内容不会由常识补写，范围和上下限也不会被改成精确值。它还能生成七类交付物，并提供 uplift 评分器：裸模型与挂 Skill 各运行三次取中位数，按容差逐字段评分，仓库不虚构实测分数。
>
> 下面实际演示。工作区支持 PDF、DOCX、TXT 和 Markdown，可以查看 PDF 原文与解析文本。文件在浏览器本地解析，只有开始分析后，选中的片段才发送到用户配置的接口。
>
> 用户可以自由勾选文档；三到十篇会进入比赛严格模式。本次选择三篇，通过 OpenAI-compatible API 调用 Qwen。每篇独立处理，单篇失败不会让整批结果静默缺失。
>
> Agent 依次完成文献解析、数据提取、单位规范化、条件核验、冲突检测和报告生成。页码必须来自真实提交页面，证据句必须能在原文片段中定位，否则会降为低可信并进入人工复核。
>
> 覆盖矩阵说明每篇检查了哪些页面、产生多少记录及失败原因。可比性护照从证据定位、字段完整性、测试条件和单位可比性四个维度评分。
>
> 每个性能值都是独立记录，保留材料原名与规范名、原始与规范化数值、工艺、条件、页码和最短证据原文，可以直接回到引用核查。
>
> 未报告的温度、频率、方向或密度会被显式列出；只有关键条件兼容的数据才参与冲突检测。结果可导出 JSON、CSV、Markdown、覆盖矩阵和可比性护照，便于复核、入库和下游 Agent 复用。
>
> MatTrace 以完整 Skill 为核心，以 Agent 作为演示入口，并通过一百零八项测试、动态与静态浏览器回归、独立 Skill 校验和 MIT 许可证保证可运行、可复现、可扩展。
>
> 希望 MatTrace 让材料数据整理从一次性摘录，变成可信、可审计、可复用的数据资产。感谢各位评委观看。

## 四、剪辑与避坑提示

- 开场标题不超过 3 秒才进入内容；上表将标题与首页淡入合并在前 8 秒内。
- 模型真实等待可以加速，但不要剪掉“逐篇进度”和六阶段状态，否则会削弱工程完整性证明。
- 不要在视频中念出或显示 API Key，也不要把 Key 写入字幕、终端或仓库。
- 不要称网页为比赛最终 Skill。始终使用“正式交付是 Skill，Agent 是演示入口”的表述。
- 如果本次真实分析没有发现冲突，应说“系统完成了冲突检测，当前没有可比较冲突”，不能为了展示效果制造冲突。
- 如果某篇结果为 `no_evidence`，不要重新录到它消失；这是覆盖审计的能力证明，可以直接解释“每篇都有明确结论，不会静默遗漏”。
- 不要展示示例 uplift 数字并称其为项目实测结果。若后续完成六次真实评测，可再把经留痕的中位数和 uplift 加入字幕。
- 仓库正式上传后，可以在结束卡底部补充短链接或二维码，但不要挤压项目名和 Skill 名称。
